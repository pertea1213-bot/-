# 온톨로지·FDE 플랫폼

업무 구조도(온톨로지)와 현장 실행형 엔지니어(FDE) 방식으로 **문제를 정의·검증·개선**하는 컨설팅·교육 플랫폼입니다.
교안(온톨로지·현장배치형 엔지니어 양성교육, 169장)과 원문 제20장 *인사 직능 온톨로지 FDE 컨설팅 과업 교육사례*(H-701 / HR-047)를 바탕으로, 교안의 규칙을 **화면이 아니라 코드로 강제**합니다.

> 사례의 회사·사람·수량·비용·기간은 교육을 위해 만든 **가상 자료**입니다. 실제 기업의 실행·성과나 저자의 검토 완료를 뜻하지 않으며, ‘준비’는 배치 가능성의 내부 운영 정의일 뿐 근로계약 유효성·노동법상 의무·임금을 판단하지 않습니다.

기존 저장소 루트의 PM 도구(`../server.js`)와는 **별개의 독립 앱**입니다.

## 실행

```bash
cd fde-platform
npm install
npm start            # http://localhost:5100  (PORT, HOST, FDE_DB_PATH 로 변경)
npm test             # 시스템 시험 27 + 사례 수치·통합 시험 등 32개 (약 5초)
```

- 개발 모드 데모 비밀번호는 서버 시작 로그에 표시됩니다(`fde-demo-1234`). 계정: `admin consultant1 fde1 exec1 hr1 manager1 it1 sec1 field1 reviewer1 learner1` (+ `consultant2 manager2 it2 field2 learner2`).
- **운영 모드**(`NODE_ENV=production`)는 `DEMO_PASSWORD` 가 없으면 **시작을 거부**합니다(알려진 기본 비밀번호 금지). 데모 계정 목록은 `EXPOSE_DEMO_USERS=1` 일 때만 공개합니다.
- DB는 `data/fde.db`(SQLite, `.gitignore`). 사례를 초기 상태로 되돌리려면 운영자(admin)로 `POST /api/engagements/:id/reset` — 처리 기록(audit)은 지워지지 않습니다.

각 사례에는 문제 문장·모집단 표·지표와 분모·경제성 가정·**모델링 선택(원문과 구분)**이 사례 개요로 붙어 있고, 학원·의류·빵은 원고의 21개 실습도 사례별로 옮겼습니다. 다른 업종은 화면에서 어댑터를 만들어 이식합니다(코어 코드 변경 없음).

사례마다 모집단 구조가 달라 엔진을 일반화했습니다. **부족 = max(0, 요구 − 승인)** 이고 승인이 요구를 넘으면 초과로 표시합니다(빵 분기 A 잔량 140). 입력이 요구보다 크면(의류 재단 420 vs 주문 400) 부족을 설명하고 남은 칸을 ‘초과분’으로 따로 둡니다(예비 재단 20은 가용 재고가 아님). 학원처럼 모집단이 여럿인 사례는 재등록 54명만 엔진에 올리고 상담 40건·수업 기회 216건은 지표 표로 둡니다(원문: 서로 다른 분모를 한 문장에서 비교하지 않는다).

## 설계 원칙 — 코드가 강제하는 것

`src/engine.js` 가 교안의 불변 규칙을 한곳에서 지킵니다. 모두 시험으로 고정되어 있습니다.

1. **한 대상은 한 칸** — `classifyItem` 은 정확히 하나의 칸만 돌려준다. 우선순위: 진행(확인 중) → 미확인(근거 없음/불명/식별번호 없음) → 검토(미충족·열린 보류·배정 이상) → 준비.
2. **근거가 없으면 0이나 합격이 아니라 미확인** — 자료 식별번호 없는 `verified` 는 미확인(T6).
3. **전달 ≠ 수신 ≠ 적용 ≠ 승인** — `delivered` 는 적용이 아니다(T5).
4. **조치 경로 승인은 수량을 올리지 않는다** — 수량은 확인된 근거로만 바뀐다(T7·T8).
5. **AI/OCR 추출값은 후보** — 근거 자료 관리자가 확정하기 전에는 판정 근거가 아니다(X4).
6. **이중 시간축** — 발생 시각(basis)과 기록 시각(known)을 분리해, 지난 기준일 보고서를 후행 입력·정정이 덮어쓰지 않는다(T11·A3). 근거·결재·처리 기록은 추가 전용.
7. **분모 0은 100%가 아니다** — 완료율·승인율은 `null`(산출 불가)(X5).
8. **세 계산 확인식 + 하위 범주 합계** — 항상 잔차를 표시하고 숨기지 않는다. 합계 일치 ≠ 정확하므로 대상 키 단위 이동 비교(`transitions`)와 14개 기간 행 검증을 따로 둔다.
9. **제안은 플랫폼, 승인은 담당자, 실행은 업무 시스템** — 컨설턴트·FDE·운영자는 승인할 수 없고, 제안자는 자기 조치를 승인할 수 없으며, 요청자는 자기 연계 요청을 결재할 수 없다. 권한 없는 시도는 거부되고 *처리 기록에 남는다*.
10. **플랫폼 결재와 외부 수락은 별도 상태**, 쓰기 연계는 읽기 → 시뮬레이션 → 수동 승인 → 제한된 실운영 순으로 한 단계씩.

## 역할과 권한

경영진·인사 담당·현업 관리자·정보 담당·노무·보안 담당(업무 책임자) / 컨설턴트·FDE / 현장 담당자·검토자 / 교육생·운영자. 근거를 *확정*할 수 있는 역할은 **업종 어댑터가 정한 책임자뿐**입니다(예: HR의 계정 근거 = 정보 담당). 현장 담당자는 후보로만 등록하고 본인이 입력한 근거만 봅니다(자료 번호·메모도 가림). 전체 매트릭스는 화면 *업무 구조도 → 실행 작업·권한* 에서 코드와 같은 출처로 생성됩니다.

## 이 플랫폼이 *아닌* 것 / 한계

- **실제 인사 시스템·계정 시스템과 연결되어 있지 않습니다.** 외부 반영은 모의 원장으로 구현되어 있으며 실연동은 별도 수용 시험이 필요합니다(교안: ‘실제 배포·구축 기록이 아니다’).
- **원문에는 대상별 행 데이터가 없습니다.** 시드의 대상별 행·날짜·자료 번호는 원문의 합계·부서별 표를 재현하도록 만든 **합성 데이터**입니다. 8명·4명의 *원인*은 원문처럼 판정하지 않았고, 원인 후보 매트릭스는 학습자가 채우는 작업 영역입니다.
- ‘진행’은 *확인이 진행 중이라고 기록된 대상*입니다. 착수(입사 확인)가 확인되면 근거가 없는 요건에 시스템이 `pending` 을 열어 진행으로 보이게 하고, 실제 확인 전에는 준비로 올라가지 않습니다.
- 발생 시각은 **일 단위**로 비교합니다(현장 입력은 날짜만 적는 경우가 많음). 같은 날이면 나중에 기록된 것이 우선합니다.
- 인증은 데모 수준(역할별 공용 비밀번호, 로그인 시도 제한만)입니다. 실사용 전에 개별 계정·SSO·감사 보존 정책을 정해야 합니다.
- UI는 자동화 테스트가 아니라 헤드리스 브라우저 수동 순회(18개 화면 오류 0, 흐름 검증, XSS 페이로드 4종)로 확인했습니다. `npm test` 는 서버·엔진 범위입니다.
- 법률·회계·노무 판단은 하지 않습니다. 해당 책임자가 별도로 확인합니다.

## 교안·원문에서 발견한 정합성 문제

화면의 *점검표·FAQ·루브릭 → 자료 정합성 메모* 에도 있습니다. (1) 원문은 부족 17을 검토·미확인·진행의 합과 비교하라고 하나 그 합은 12이고 나머지 5는 미입사(예비)입니다. (2) 모듈 A 시간이 3시간(시간표)과 2.5시간(표지)로 다릅니다. (3) 대안 2의 비용 150,000원은 대상 4명이 아니라 재교육 3명 기준입니다. (4) ‘승인’이 최초 승인·조치 경로 승인·결재의 뜻으로 겹쳐 쓰입니다. (5) 원문에 ‘가리식별번호는지’ 같은 일괄 치환 오류가 있어 실습 본문을 옮길 때 바로잡았습니다. (6) 정본 스킴 문서의 7개 업종 중 학원·의류·빵 원고는 수록했고, 카페·미용실·김 제조·기계금속 원고는 제공되지 않아 수록하지 않았습니다 — 원고가 있으면 같은 방식으로 추가할 수 있습니다. (7) 학원·의류·빵 원고의 실습은 ‘현장 적용과 해설’ 라벨이 없고 표·도해 중심이라, 서술 문단만 추출했습니다(표·도해는 원고 PDF 참고). (8) 사례 개요의 ‘모델링 선택’(예: 학원 미정 12 = 검토 10 + 미확인 2, 빵 격리 40 = 예비, 의류 보류 36의 칸별 배분)은 원문이 직접 정한 분류가 아니라 이 플랫폼의 선택이며 화면에 그렇게 표시합니다.

## API 개요

`POST /api/auth/login` 후 `Authorization: Bearer <token>`. 주요 경로(`:id` = 과업): `GET /engagements/:id`(스냅샷·기준선·품질·보호 지표) · `/items/:itemId` · `POST /evidence` `/ingest` · `/transitions` `/periods` · `/hypotheses` · `/interventions`(`submit decide start outcome close stop`) · `/scenarios/:sid/simulate` · `/sync` · `/forms/:no` · `/closes` `/compare` `/report` · `/audit` · `POST /tests/run` · `/content/:name` · `/learn/*`. 응답 오류는 `{error}` 이며 권한 거부 403, 충돌 409, 검증 400.
